# 小红书保存选项与快捷指令

服务端自动判断链接是视频还是图文。快捷指令只保留两个选项：

| 菜单选项 | save_images | enable_ocr |
|---|---|---|
| 只保存正文（默认） | false | false |
| 保存图片并提取文字 | true | true |

视频会自动下载音频并执行语音转写，两个菜单选项都不会关闭视频转写。图文笔记选择“只保存正文”时不下载图片；选择“保存图片并提取文字”时保存图片并执行 OCR。没有文字的图片不会生成空的 OCR 段落。

## 修改 iOS 快捷指令

1. 保留已有的“接收共享输入／输入为空则获取剪贴板”及 URL 提取步骤。
2. 在“获取 URL 内容”之前加入“从菜单中选取”，提示“保存哪些内容？”，添加上表两项。
3. 在菜单的两个分支中各建立一个“字典”，字段名为 `save_images` 和 `enable_ocr`。**两项的类型都选“布尔值”**，按表设置是／否。
4. 每个分支都用“设定变量”将字典存为同一个变量 `保存选项`。
5. 菜单结束后，分别用“获取字典值”从 `保存选项` 读取这两项，并设置变量 `保存图片`、`识别文字`。
6. 在现有“获取 URL 内容”操作中保持 POST、请求体 JSON 及原有 url/title/original_url 字段，添加 `save_images` 与 `enable_ocr` 两个字段，类型为“布尔值”，值分别插入 `保存图片`、`识别文字`。
7. 加入“生成 UUID”，保存为变量 `任务ID`，并在 POST 的 JSON 中添加 `task_id`，值为 `任务ID`。
8. 在 POST 请求头中添加 `X-Fc-Invocation-Type`，值为 `Async`。FC 会返回空的 `202 Accepted`，不要再从这个响应读取 `status` 或 `message`。
9. POST 返回后立即加入“显示通知”：`✅ 已提交，云端处理中`。此时上传已经完成，快捷指令无需一直等待 POST 响应。
10. 通知后使用“重复”循环，每次先等待 10 秒，再 GET：`https://audio-wiki-api-pedfgmuuew.cn-hongkong.fcapp.run/api/tasks/任务ID`。
11. 从查询响应中获取 `message`。如果 `message`“有任何值”，就显示第二条通知并“停止快捷指令”；如果没有值，直接进入下一轮。处理中和排队中的任务都不返回 `message`，成功或失败时才返回最终提示。
12. 建议最多重复 60 次（约 10 分钟）。循环结束仍未完成时显示“任务仍在后台处理，请稍后同步 Obsidian”，不要自动重提原链接。

这种方式会让快捷指令在后台轮询，但首次 POST 会立即结束并显示提交成功。如果希望快捷指令完全退出后仍由云端主动推送最终结果，需要另行接入 Bark、Pushcut 等推送服务。

如某版本的“获取 URL 内容”无法把变量填入布尔字段，可在每个菜单分支直接调用 POST，两个布尔值在该分支中固定按表设置。

菜单中“默认”指默认行为，不是自动跳过菜单。若希望常用入口完全不用选择，可复制成两个快捷指令：日常版不加菜单、两个字段固定 false；可选版保留上述菜单。

## 请求示例：只提取文字

```json
{
  "url": "https://xhslink.cn/o/example",
  "task_id": "快捷指令生成的 UUID",
  "save_images": false,
  "enable_ocr": true
}
```

状态查询成功示例：

```json
{
  "task_id": "快捷指令生成的 UUID",
  "status": "succeeded",
  "filename": "示例笔记.md",
  "message": "✅ 已保存：示例笔记.md"
}
```

两个字段缺省均为 false；字符串 `"false"`、数字 `0/1` 会被拒绝，避免误上传。新开关当前仅作用于小红书图文；视频仍执行音频转写流程。
